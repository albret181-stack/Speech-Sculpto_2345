# Speech Sculptor — план развития

Актуализация: 2026-11-03. Этот план описывает **приоритеты**, а не обещание готовности. В GitHub Releases обнаружен `v1.0.1` (27.10.2026), тогда как `README.md` описывает 0.3, а `QA_REPORT.md` — тестирование 0.9. Перед реализацией и выпуском сверять возможности с исходниками, установленной сборкой и последним релизом.

## Продуктовая цель
Пользователь загружает или записывает речь на Mac, получает объяснимый локальный анализ и конкретные упражнения, затем сравнивает результат. Приватность и честная маркировка приблизительных измерений обязательны.

## Приоритеты и критерии

### P0 — надёжность основного сценария
- **Импорт и запись аудио:** поддерживаемые форматы, длительные файлы, ошибки декодирования, повторный импорт. Готово, когда сценарии воспроизведены на настоящем Mac и не теряется исходная запись.
- **Разрешения и локальный Speech:** проверка отказа в доступе, отсутствия локальной поддержки ru-RU, корректные сообщения. Не делать скрытого переключения на облако.
- **Актуальность документов и выпусков:** сверить README, версию приложения, релизные артефакты и workflow публикации; описать безопасный путь от PR до выпуска.

### P1 — качество анализа
- Отдельно оценить точность распознавания (WER) и качество определения слов-паразитов (precision/recall/F1) на независимых реальных примерах с согласия участников.
- Для пауз, темпа и интонации показывать границы достоверности; не выдавать неприменимые показатели за факты.
- Понятные рекомендации и повторная попытка: сравнение «до/после» без искусственно завышенных выводов.

### P2 — расширение опыта
- Пакетный импорт и отчёт по нескольким записям без передачи аудио в облако.
- Удобный обзор истории и прогресса.
- Улучшение обновлений: различать уведомление о релизе и настоящую автоустановку; последняя потребует подписывания, нотарификации и проверки перехода N → N+1.

## Что проверять на каждом этапе
Разделять **проверку алгоритма**, **сборку macOS**, **ручной запуск приложения** и **качество на живой речи**. Не закрывать последнюю категорию синтетическими фразами. Вести задачи через GitHub Issues; для каждой задачи — конкретные критерии и PR со следами проверок.
